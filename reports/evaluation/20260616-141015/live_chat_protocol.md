# Live Chat Evaluation Protocol

ใช้ไฟล์นี้สำหรับทดสอบว่า AI คุยเหมือนกัปปิตันจริงไหม จากการให้เพื่อนเข้ามาพิมพ์คุยเอง

## รูปแบบไฟล์ที่ใช้

ระหว่างเก็บข้อมูล ผู้ทดสอบกรอก CSV จำนวน 1 row ต่อ 1 รอบทดสอบ ถ้าคนเดิมทดสอบหลายรอบ ให้เพิ่ม row ใหม่โดยใช้ `evaluator_id` เดิมได้ Template ว่างถูกลบหลังการเก็บข้อมูลเสร็จแล้ว เพราะผลดิบเป็นข้อมูลภายในและไม่ควรเผยแพร่ใน public repository

CSV header ที่ใช้ในการทดลอง:

```csv
evaluator_id,num_user_prompts,captain_similarity,context_following,problem_level,acceptable_response_count,unacceptable_response_count,notes
```

## วิธีทดสอบ

1. เปิด server ด้วยโมเดลปัจจุบัน
2. ให้เพื่อนเข้ามาคุยกับ AI แบบธรรมชาติ
3. ให้คุยประมาณ 10-15 ข้อความจากฝั่ง user
4. ไม่ต้องบอกเพื่อนว่าควรทดสอบคำถามอะไรแบบเป๊ะ ๆ
5. หลังคุยเสร็จ ให้เพื่อนกรอก CSV ตาม schema ด้านบน

## แนวทางหัวข้อที่ให้คุย

- ทักทาย
- ชวนกินข้าว
- ชวนเล่นเกม
- ชวนไปเที่ยว/เดินเล่น
- บ่นเหนื่อย เครียด นอย
- ถามชื่อ
- ถามว่าเป็น AI ไหม
- คุยต่อเนื่องอย่างน้อย 3-5 turn ในบางช่วง

## ช่องใน CSV

- `evaluator_id`: รหัสผู้ทดสอบ เช่น `rater1`
- `num_user_prompts`: จำนวนข้อความที่ผู้ทดสอบส่งให้ AI ทั้งหมดโดยประมาณ
- `captain_similarity`: โดยรวมเหมือนกัปปิตันไหม
- `context_following`: จำและใช้บริบทในบทสนทนาถูกไหม
- `problem_level`: มีปัญหาหลุด/มั่ว/คำแปลกเยอะแค่ไหน
- `acceptable_response_count`: จำนวนคำตอบที่ผู้ทดสอบยอมรับได้ เช่น เหมือนกัปปิตัน ตอบตรง หรือคุยต่อได้เป็นธรรมชาติ
- `unacceptable_response_count`: จำนวนคำตอบที่ผู้ทดสอบยอมรับไม่ได้ เช่น ไม่ตรง มั่ว หลุด หรือรบกวนการคุย
- `notes`: หมายเหตุ เช่น ตัวอย่างคำตอบที่ดีหรือแย่

## เกณฑ์คะแนน 1-5

สำหรับ `captain_similarity` และ `context_following`:

- 1 = แย่มาก ไม่เหมือน/ไม่ตามบริบทเลย
- 2 = ค่อนข้างแย่ เหมือนหรือตามบริบทน้อย
- 3 = พอใช้ มีบางช่วงดีแต่ยังหลุดชัด
- 4 = ดี เหมือนหรือตามบริบทเป็นส่วนใหญ่
- 5 = ดีมาก เหมือนกัปปิตันมากและตามบริบทแทบไม่สะดุด

สำหรับ `problem_level` ให้กลับด้าน:

- 1 = แทบไม่มีปัญหา
- 2 = มีปัญหาเล็กน้อย
- 3 = มีหลุดบ้างแต่ยังพอรับได้
- 4 = หลุดค่อนข้างเยอะ
- 5 = หลุดเยอะจนรบกวนการคุย

## วิธีนับ acceptable/unacceptable response

ให้ผู้ทดสอบนับจากความรู้สึกระหว่างคุย ไม่ต้องละเอียดถึงขั้น log ทุกประโยค

นับเป็น `acceptable_response_count` ถ้าคำตอบ:

- เหมือนสไตล์กัปปิตัน
- สั้นและเป็นธรรมชาติ
- ตอบตรงกับที่ถาม
- ใช้บริบทก่อนหน้าได้ถูก

นับเป็น `unacceptable_response_count` ถ้าคำตอบ:

- ตอบไม่ตรงคำถาม
- เดาสถานที่/สถานะ/ข้อมูลส่วนตัวเอง
- มีคำแปลก เลขหลุด หรือดูมั่ว
- ยาวหรือเป็นผู้ช่วยทางการเกินไป
- วกวนหรือทำให้คุยต่อยาก

ตัวอย่าง:

ถ้าเพื่อนส่ง 12 ข้อความ แล้วรู้สึกว่า AI ตอบได้ในระดับยอมรับได้ 8 ครั้ง และยอมรับไม่ได้ 4 ครั้ง:

```text
num_user_prompts = 12
acceptable_response_count = 8
unacceptable_response_count = 4
```

ทุกคำตอบต้องจัดเข้ากลุ่มใดกลุ่มหนึ่ง ดังนั้น `acceptable + unacceptable` ต้องเท่ากับ `num_user_prompts`

## วิเคราะห์หลังเก็บครบ

เก็บไฟล์ของผู้ทดสอบแยกกัน เช่น `live_rater1.csv` ถึง `live_rater5.csv` แล้วรัน:

```powershell
captain-env\Scripts\python.exe evaluation\analyze_live_chat.py `
    --run-dir 20260616-141015 `
    --eval-csvs live_rater1.csv live_rater2.csv live_rater3.csv live_rater4.csv live_rater5.csv
```

คำสั่งนี้ควรรันหลังรวมไฟล์ทดสอบครบแล้วเท่านั้น
